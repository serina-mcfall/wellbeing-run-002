2. THE DEFECT
-------------
prompts/accessibility.md's required-output example showed:

      "unmet_requirement": "visible-focus-indicator",

That is the pre-C-02 kebab-case form. The requirement registry C-02 landed
(apparatus/accessibility/requirement-registry.js, mirrored in
control/accessibility_registry.py) does not contain it, and
severity.apply_severity_policy accepts only identifiers the registry
contains. A reviewer that copied the example in its own prompt therefore
produced a FAILURE finding rated INVALID, and the entire review was refused
as CLASSIFICATION_INVALID. Fail-closed and safe, but the qualitative FAIL
path could never produce a usable finding.

10. RESIDUAL GAP — NOT CLOSED BY THIS AMENDMENT, CLOSED SEPARATELY
------------------------------------------------------------------
Correcting the example makes the prompt's one worked example valid. It does
NOT tell the reviewer the other sixteen identifiers. The prompt instructs
the reviewer to read product/ACCESSIBILITY.md, which contains the source
PROSE ("visible focus"), not the canonical IDs — so a reviewer citing a
requirement other than the example would still have to infer the
ACC-DOD-*/ACC-COG-* form from a single sample, and a wrong inference is a
CLASSIFICATION_INVALID hold.

This was NOT solved by widening the frozen-file change, which would have
exceeded the authorisation. It is solved at dispatch instead: the canonical
identifier list is injected into the {{evidence}} substitution the
Supervisor already owns and already fills. No further frozen-file change,
no parser alias, one source of truth — the registry itself renders the
list. See the qualitative dispatch work recorded in the handover.
