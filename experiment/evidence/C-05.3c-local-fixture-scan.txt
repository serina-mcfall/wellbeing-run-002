2. WHAT WAS BUILT
-----------------
apparatus/accessibility/fixture-product/{clean,violations}/

Each: package.json (build + start scripts, no dependencies),
package-lock.json, build.js, server.js, index.html. The index.html files
are BYTE COPIES of apparatus/accessibility/fixtures/{clean,violations}.html
— the pages run.test.js already proves the individual checks against — and
fixture-product-pages.test.js asserts that in both directions so they
cannot drift.

WHY NOT AT THE REPOSITORY ROOT. PRODUCT_ENTRYPOINT and PRODUCT_LOCKFILE
resolve relative to the attempt's checkout ROOT. A root package.json would
be found by a real attempt and built and scanned as if it were TASK-001's
Next.js app. There is deliberately no root package.json in this repository
(apparatus/package.json keeps the root free for the product), and a node
test now asserts that stays true.

The tests therefore root ProductServices at
`<worktree>/apparatus/accessibility/fixture-product/<variant>`, so the
fixture is still read out of a detached worktree at an exact commit: the
provenance path under test is the production one.

5. THE DEFECT THIS FOUND — AND IT COULD ONLY BE FOUND BY RUNNING IT
--------------------------------------------------------------------
On the FIRST real failure run, all four composite checks produced UNCITED
findings:

    UNMAPPED  FOCUS_ORDER_VISIBLE_NO_TRAPS          condition=None
    UNMAPPED  LABELS_AND_TEXT_ERRORS                condition=None
    UNMAPPED  REDUCED_MOTION_NO_FLASHING_AUTOPLAY   condition=None
    UNMAPPED  AXE_SCAN                              condition=None

…while the signals those checks had genuinely reported were:

    FOCUS_ORDER_VISIBLE_NO_TRAPS  FORWARD_TRAPPED, BACKWARD_TRAPPED,
                                  NOT_ALL_REACHABLE
    LABELS_AND_TEXT_ERRORS        NO_ACCESSIBLE_NAME,
                                  INVALID_WITHOUT_TEXT_ERROR
    AXE_SCAN                      label, page-has-heading-one (+3 unmapped)

CAUSE. `apparatus/accessibility/run.js` writes
`{checks: [...], details: {CHECK_ID: {...}}}` — results and diagnostics in
SEPARATE top-level fields. `ProductServices.scan` returned
`payload["checks"]` alone. `accessibility_evidence.findings_for` reads
`check.get("detail")`, which therefore never existed, so
`routing.accessibility_check_signals` was handed None on every real run and
returned no signals every time.

EFFECT. Not a hole — a DOWNGRADE. G6's approved composite sub-condition
structure could never fire in production. Every composite failure collapsed
to one uncited finding, which severity.py rates INVALID with
merge_blocked=True. Nothing merged that should not have, which is exactly
why no test caught it: every assertion about blocking stayed true. What was
lost was the citation — the reviewer was told "no requirement cited" about
failures whose requirement the registry already names.

FIX. `control/accessibility_services.py::_with_details`, called from
`scan`. It joins the two halves by check_id at the one seam where run.js's
output becomes the control plane's. Rejected alternatives: changing run.js
to nest detail inside each check (changes a schema-shaped output and every
fixture that consumes it), and threading a second map through run_attempt
and AttemptOutcome (a new parameter on two frozen dataclasses for one
consumer).

NO POLICY WAS CHANGED. Not one mapping table, severity rule, requirement
identifier or verdict rule was touched. The fix delivers detail to code
that already existed and was already approved. Both before and after, every
finding from a failing check has merge_blocked=True; the fix converts
uncited-INVALID-blocking findings into cited-P1-blocking ones and leaves
the deliberately unmapped ones exactly as they were. Measured: 7 findings
before, 14 after, all 14 blocking.

Regression cover: tests/test_c05_3c_scan_detail_join.py, 11 tests,
including one that still asserts an unmapped axe rule stays uncited and
blocking, and one that asserts an absent detail stays ABSENT rather than
becoming an empty dict — "nothing we could read" and "no sub-condition we
recognise" must not collapse into each other.


6. A SECOND DEFECT, IN THE TEST HARNESS ITSELF
-----------------------------------------------
The first real run of tests/test_c05_3c_local_fixture_scan.py LEAKED EIGHT
stale git worktree registrations. Its cleanup called
`ProductServices.dispose()`, which removes `self.checkout` — but this test
roots ProductServices at a SUBDIRECTORY of the worktree, so dispose deleted
the fixture directory and left the worktree registered. Once the
TemporaryDirectories went away the registrations became unprunable garbage
in a list this repository shares with eleven live subagent worktrees.

Found by printing `git worktree list`, not by any assertion. Pruned (the
eleven agent worktrees were untouched and verified present before and
after: 12 entries before, 12 after). The cleanup now removes the worktree
ROOT, and NoWorktreeLeakCase asserts the count is unchanged.

THE FIRST VERSION OF THAT GUARD WAS VACUOUS. It pruned inside the test body
BEFORE asserting, so it passed with the helper stubbed to `return`. Caught
by mutating the helper and watching the guard stay green — which is the
entire reason for mutating it. Restructured so the tidy-up is an
addCleanup, after the measurement. Re-mutated: FAILED, "13 != 12 : an
attempt checkout leaked a worktree registration". Restored, sha256
